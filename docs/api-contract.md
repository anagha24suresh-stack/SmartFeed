# FoodRoute Shared API Contract & Data Models

This contract defines the shared data schemas and endpoints agreed upon by all three modules.

---

## 1. Core Data Models

### 1.1 Donation
Represents surplus food offered by a donor.
```json
{
  "id": 1,
  "donor_name": "Green Leaf Restaurant",
  "food_type": "Cooked meals",
  "quantity_kg": 40.0,
  "remaining_kg": 40.0,
  "location": {
    "lat": 12.97,
    "lng": 77.59
  },
  "ready_time": "2026-11-05T14:00:00",
  "expiry_time": "2026-11-05T20:00:00",
  "pickup_window": {
    "start": "14:00",
    "end": "17:00"
  },
  "status": "open"
}
```

### 1.2 Request
Represents food assistance needed by a receiver / shelter.
```json
{
  "id": 7,
  "receiver_name": "Hope Shelter",
  "quantity_kg": 60.0,
  "remaining_kg": 60.0,
  "location": {
    "lat": 12.93,
    "lng": 77.62
  },
  "delivery_window": {
    "start": "15:00",
    "end": "19:00"
  },
  "need_level": 4,
  "status": "open"
}
```

### 1.3 Depot
Distribution and vehicle starting/ending hub.
```json
{
  "id": 1,
  "name": "North Depot",
  "location": {
    "lat": 13.0,
    "lng": 77.58
  }
}
```

### 1.4 Vehicle
Fleet vehicle assigned to a specific depot.
```json
{
  "id": 1,
  "depot_id": 1,
  "capacity_kg": 100.0,
  "available_from": "09:00",
  "available_to": "21:00",
  "is_active": true
}
```

### 1.5 Match
Matching result produced by Module 1, consumed by Module 2.
```json
{
  "match_id": 12,
  "donation_id": 1,
  "request_id": 7,
  "allocated_kg": 40.0,
  "priority_score": 0.87
}
```

### 1.6 Route
Routing solution generated by Module 2, visualized by Module 3.
```json
{
  "vehicle_id": 1,
  "depot_id": 1,
  "stops": [
    { "type": "pickup", "donation_id": 1, "kg": 40.0, "arrive": "14:20", "depart": "14:35" },
    { "type": "delivery", "request_id": 7, "kg": 40.0, "arrive": "15:10", "depart": "15:25" }
  ],
  "total_distance_km": 18.4,
  "total_time_min": 95
}
```

## 2. API Endpoints Overview

### Auth & User Management
- `POST /auth/register` - Register a new user (role: `donor`, `receiver`, or `admin`)
- `POST /auth/login` - Authenticate and retrieve JWT access token
- `GET /auth/me` - Get current authenticated user profile

### Core Entities (CRUD)
- `GET /donations` & `POST /donations` - List and create donations
- `GET /donations/{id}` & `PUT /donations/{id}` & `DELETE /donations/{id}`
- `GET /requests` & `POST /requests` - List and create food requests
- `GET /requests/{id}` & `PUT /requests/{id}` & `DELETE /requests/{id}`
- `GET /depots` & `POST /depots` - List and create depots
- `GET /vehicles` & `POST /vehicles` - List and create fleet vehicles

### Urgency Scoring & Matching (Module 1)
- `GET /scores` - Retrieve calculated urgency scores for all active donations and requests
- `POST /matching/run` - Trigger matching algorithm and store results
- `GET /matching/results` - Fetch latest matches and unmatched items with reasons

### Routing Optimization (Module 2)
- `POST /routing/plan` - Build vehicle routes from matches
- `GET /routing/routes` - Fetch latest planned routes
- `GET /routing/summary` - Metrics: total distance, food delivered, unserved
- `POST /routing/replan` - Re-plan after dynamic updates
